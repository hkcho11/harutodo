# 운영 환경 화면 캡처 가이드

## 목적

개발 환경의 샘플 데이터가 아니라 실제로 두 사람이 사용 중인 운영 경험을
보여준다. 다만 포트폴리오의 목적은 개인 생활을 공개하는 것이 아니라 제품의
정보 구조, 반복 사용성, 실시간 공유 경험을 증명하는 것이다.

## 원칙

1. 원본 캡처는 Git 저장소에 넣지 않는다.
2. 이름, 일정 제목, 장소, 초대 코드, 이메일, 알림 내용은 공개 전에 검토한다.
3. 개인 주기 정보가 보이는 캘린더는 사용하지 않거나 해당 영역을 완전히 가린다.
4. 실제 운영 화면을 과도하게 편집해 존재하지 않는 기능처럼 보이게 하지 않는다.
5. 익명화된 최종 PNG/WebP만 `docs/portfolio/assets/`에 추가한다.
6. 모바일 상태 표시줄의 통신사, 알림 아이콘, 배터리 정보도 필요하면 잘라낸다.

## 촬영 전 준비

- 두 사람의 표시 이름을 포트폴리오 공개용 별칭으로 잠시 바꾸는 방법이 가장 안전하다.
- 민감한 일정은 촬영 화면 밖의 날짜로 이동하거나 제목을 임시로 일반화한다.
- 위치 정보가 포함된 일정은 선택하지 않는다.
- 개인 주기 표시가 활성화돼 있다면 촬영 중 캘린더에서 끄거나 해당 월을 피한다.
- 촬영 후 임시 변경을 원래대로 되돌린다.
- 두 사람 모두 공개할 화면과 가공 범위에 동의해야 한다.

## 필수 장면

### 1. 오늘 홈

권장 파일명: `product-home.webp`

보여줄 내용:

- 오늘 날짜
- 함께·본인·파트너 그룹 구분
- 완료 진행률
- 3~6개의 투두
- 하단 탭과 추가 버튼

권장 샘플 문구:

- 함께: 장보기 목록 정리
- 나: 숙소 예약 확인
- 파트너: 저녁 식당 알아보기

가릴 내용:

- 실명
- 구체적인 병원·금융·가족 일정
- 주소나 예약번호

### 2. 월간 캘린더

권장 파일명: `product-calendar.webp`

보여줄 내용:

- 일정이 여러 날짜에 분포된 실제 사용 밀도
- 공휴일·토요일 구분
- 함께·본인·파트너 일정 색상
- 선택 날짜와 하단 일정 목록
- 날짜·시간·반복·참여자를 입력하는 일정 추가 화면
- 장소 검색 결과와 선택한 장소의 지도 미리보기

가릴 내용:

- 개인 주기 표시 전체
- 여행 숙소명, 병원명, 집 주소

### 3. 마이페이지

권장 파일명: `product-mypage.webp`

보여줄 내용:

- 두 사람의 프로필과 연결 관계
- 커스텀 그룹 관리
- 알림과 개인화 설정

가릴 내용:

- 이메일과 초대 코드
- 실명 또는 식별 가능한 프로필 정보
- 가족 실명

### 4. 지난 미완료 정리

권장 파일명: `product-carryover.webp`

보여줄 내용:

- 실제 반복 사용에서 생기는 미완료 항목
- 여러 항목 선택
- 오늘 또는 다른 날짜로 이동하는 흐름

포트폴리오 메시지:

> 완료하지 못한 일을 죄책감으로 남기지 않고 다음 계획으로 정리하도록
> 반복 사용 부담을 줄였습니다.

### 5. 알림 설정

권장 파일명: `product-notifications.webp`

보여줄 내용:

- 아침 요약
- 저녁 리마인더
- 일정 사전 알림
- 알림 내용 공개 여부

가릴 내용:

- 브라우저나 OS에 노출된 실제 알림 내용
- 사용자 이름

### 6. 홈 화면 또는 Scriptable 위젯

권장 파일명: `product-widget.webp`

보여줄 내용:

- 실제 기기 홈 화면에서 접근 가능한 상태
- 월간 캘린더와 투두 표시

가릴 내용:

- 다른 앱의 알림 배지
- 개인 사진, 배경화면, 금융·건강 앱
- 기기의 다른 위젯에 표시된 개인정보

홈 화면 전체를 촬영하기보다 위젯 영역만 crop하는 것을 권장한다.

## 선택 장면

### 커플 연결

초대 코드는 절대 실제 값이 보이지 않게 한다. 이미 연결된 운영 계정에서는
굳이 연결 해제 후 재촬영하지 않는다. 기존 화면 목업이나 코드 기반 흐름도로
대체하는 것이 더 안전하다.

### Push 알림

알림 내용이 두 사람의 실제 생활을 드러낼 가능성이 높다. 공개용 일반 문구로
새 투두를 등록해 알림을 한 번 생성한 뒤 촬영하고 즉시 삭제한다.

## 권장 이미지 규격

| 용도 | 크기 | 형식 |
|---|---:|---|
| 모바일 단독 화면 | 750 × 1624 이상 | WebP |
| 두 화면 비교 | 각 750 × 1624 이상 | WebP |
| 위젯 crop | 가로 1000px 이상 | WebP |
| 원본 보관 | 기기 원본 해상도 | PNG |

- 공개용 WebP 품질은 80~88을 권장한다.
- 포트폴리오 웹에는 이미지당 300KB 이하를 목표로 한다.
- 가림 처리는 흐림보다 불투명한 단색 마스킹을 사용한다. 흐림은 복원되거나
  원문 형태가 추정될 수 있다.

## 최종 검수 체크리스트

- [ ] 두 사람의 실명과 이메일이 보이지 않는다.
- [ ] 주소, 장소명, 예약번호가 보이지 않는다.
- [ ] 개인 주기와 건강 정보가 보이지 않는다.
- [ ] 실제 초대 코드가 보이지 않는다.
- [ ] 다른 앱과 알림의 개인정보가 보이지 않는다.
- [ ] 배우자가 공개 범위에 동의했다.
- [ ] 실제 구현과 다른 합성 기능이 없다.
- [ ] 원본 캡처가 Git에 포함되지 않았다.
- [ ] 최종 파일 용량이 이미지당 300KB 이하이다.

## 웹 삽입 순서

1. Hero 오른쪽: `product-home.webp`
2. 실제 화면 캐러셀: CRUD 화면, 캘린더 조회·추가·장소 검색 화면, `product-mypage.webp`
3. 반복 사용 UX 사례: `product-carryover.webp`
4. 알림 시스템 사례: `product-notifications.webp`
5. 결과 영역: `product-widget.webp`

홈·캘린더·마이페이지는 서비스 전체 구조를 보여주는 필수 화면으로 사용하고,
CRUD 과정은 한 화면씩 넘겨보는 캐러셀로 제공한다.
