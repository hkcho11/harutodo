# 실사용 파트너 피드백 정리

## 인터뷰 배경

- 인터뷰 대상: 결혼 준비부터 하루투두를 함께 사용한 실사용 파트너
- 사용 맥락: 일정과 해야 할 일이 동시에 늘어나는 결혼 준비와 공동생활
- 정리 일자: 2026-07-27
- 활용 원칙: 현재 구현, 실사용에서 확인된 가치, 아이디어 단계 요청을 구분한다.

## 문제 인식

1. 캘린더와 To-do 앱을 각각 사용해 여러 앱을 번갈아 확인해야 했다.
2. 일정과 관련 할 일이 연결되어 있어도 분리 관리되어 전체 계획을 한눈에
   파악하기 어려웠다.
3. 두 사람이 같은 일정과 할 일의 담당·진행 상태를 함께 볼 통합 서비스가
   필요했다.

## 실사용에서 확인된 가치

### 캘린더와 To-do를 한 서비스에서 관리

일정과 할 일을 찾기 위해 여러 앱을 이동하는 횟수를 줄였다. 현재 제품은
일정과 투두의 직접 관계를 저장하지 않으므로 “연결 기능”으로 과장하지 않고,
하나의 서비스에서 같은 생활 맥락을 확인하는 가치로 설명한다.

### 개인·공동 To-do

함께, 본인, 파트너 항목을 구분하고 같은 화면에서 진행 상태를 공유한다.

### 커플 맞춤 개인 주기

개인 주기를 기록하고 공개 수준에 따라 파트너와 필요한 정보만 공유한다.
민감정보이므로 기능 편의성과 공개 범위 제어를 함께 설명한다.

### 정보 위계가 분명한 UI

폰트 크기, 굵기, 색상으로 핵심 정보와 보조 정보를 구분해 짧고 잦은 확인의
피로를 줄인다.

## 사용자 요청 백로그

| 요청 | 해결하려는 문제 | 현재 상태 |
|---|---|---|
| 일정-To-do 연결 | 하나의 계획이 일정과 할 일로 분리되는 문제 | 미구현·검증 필요 |
| 공동 To-do 템플릿 | 장보기와 체크리스트의 반복 입력 | 미구현·검증 필요 |
| 공동 문서 보관함 | 중요한 생활 문서가 각자에게 흩어지는 문제 | 아이디어 |
| 일정-문서 연동 | 계약 만료·제출·여행 일정에서 문서를 다시 찾는 문제 | 아이디어 |
| 문서 스캔·OCR | 종이 서류 등록의 입력 부담 | 아이디어 |
| 공동 자산·생활 관리 | 생활비·예산·공동 구매가 별도 서비스에 분리되는 문제 | 아이디어 |

## 문서 기능 사전 검토

### 권한

- `couple_id`만으로 충분한지 문서 소유자·공개 범위를 별도로 둘지 결정
- 관계 해제, 계정 탈퇴, 초대 변경 시 접근 권한 즉시 회수
- RLS와 비공개 스토리지 정책을 함께 검증

### 저장과 전송

- 저장 데이터와 전송 구간 암호화
- 공개 URL 대신 짧게 만료되는 서명 URL
- 파일 형식·용량 제한과 악성 파일 검사
- 백업, 복구, 완전 삭제와 보존 기간 정의

### 스캔과 OCR

- 촬영·OCR 처리 전 명시적 동의
- 주민번호, 계좌번호 등 민감정보 탐지·마스킹
- OCR 제공자에게 전달되는 데이터와 보관 기간 고지
- 처리 후 원본 이미지를 유지할지 즉시 삭제할지 선택권 제공

### 운영

- 문서 열람·다운로드·공유 기록
- 비정상 접근 탐지와 사용자 알림
- 데이터 유출 대응과 신고 절차

## 면접에서 설명할 핵심

> 실사용자의 다음 요청을 곧바로 기능으로 만들지 않았습니다. 특히 문서
> 보관과 스캔은 편의보다 신뢰가 먼저인 기능이므로, 권한 회수·암호화·감사
> 기록·OCR 개인정보 처리 기준을 완료 조건으로 정의한 뒤 MVP 범위를
> 결정하려고 합니다.
