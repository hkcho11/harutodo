# 지원 직무별 하루투두 포지셔닝

하루투두 한 프로젝트를 Java 개발자와 React 프론트엔드 개발자 지원에
동일한 문장으로 제출하지 않는다. 구현 사실은 유지하고 직무와 가까운
의사결정의 순서와 깊이를 조정한다.

## 공통 핵심 문장

> 결혼 준비 과정에서 기존 공유 앱의 비용과 기능 한계를 발견해 사용자와
> 직접 요구사항을 논의하고, AI 개발 도구로 탐색과 구현을 가속해 약 2주
> 만에 실사용을 시작한 커플 공유 투두·캘린더 PWA입니다. 제품 판단과
> 완료 조건, 데이터 신뢰성과 최종 검증은 직접 책임졌습니다.

## AI 활용 공통 포지셔닝

### 강조할 역량

1. 사용자 요구를 AI가 실행 가능한 완료 조건으로 변환
2. `AGENTS.md`, 프로젝트 규칙과 디자인 시스템으로 작업 맥락 고정
3. 저장소 탐색과 UI·API·DB 변경 반복을 AI로 가속
4. 권한, 정합성, 수명주기와 기존 기능 영향을 기준으로 결과 리뷰
5. lint, type-check, build와 31개 반응형 조건으로 자동 검증
6. 기준을 충족하지 못한 구현은 비용과 관계없이 제거

### 피할 포지셔닝

- AI가 코딩을 대신했으므로 기술은 별도로 공부한다.
- AI를 사용해 프론트엔드부터 백엔드까지 모두 개발했다.
- 프롬프트만 잘 작성하면 어떤 기능이든 만들 수 있다.

### 권장 포지셔닝

> 구현 생산성은 AI로 높였지만 문제 정의, 요구사항과 제약, 결과 검증과
> 출시 판단은 개발자의 책임으로 관리했습니다. 생성된 구현을 설명하고
> 검증하기 위해 프로젝트의 기술 개념을 코드와 연결해 학습하고 있습니다.

## Java 개발자 지원 버전

### 제목

공유 데이터의 권한·동시성·알림 정합성을 설계한 커플 투두 서비스

### 우선 강조

1. PostgreSQL 관계 모델과 `couple_id` 데이터 경계
2. RLS, FK, unique, check, trigger의 역할 분리
3. 초대 코드의 동시 사용을 `UPDATE ... RETURNING`으로 원자 처리
4. 일정 변경과 알림 예약을 DB trigger로 동기화
5. pg_cron과 Edge Function의 실행 책임 분리
6. 인증과 외부 요청을 신뢰하지 않는 서버 측 검증
7. 실제 장애의 원인 분석과 재현·검증 과정

### 정직하게 설명할 부분

- 하루투두의 서버 구현 언어는 Java가 아니라 TypeScript와 PostgreSQL이다.
- Java/Spring을 사용했다고 주장하지 않는다.
- 언어보다 관계형 모델, 트랜잭션, 동시성, 계층 분리와 운영 관점에서
  Java 백엔드 업무에 연결되는 설계 경험을 설명한다.

### 30초 직무 연결 답변

> 하루투두 백엔드는 Supabase 기반이지만, 핵심 문제는 특정 언어보다 데이터
> 무결성과 동시성이었습니다. 커플 권한을 RLS로 제한하고, 한 사용자가 여러
> 커플에 속하지 못하도록 unique index를 두었으며, 초대 코드는 조건부
> UPDATE로 원자적으로 선점했습니다. 이 과정에서 애플리케이션 검증과 DB
> 제약의 역할을 구분한 경험을 Java/Spring 서비스 설계에도 적용할 수 있습니다.

## React 프론트엔드 개발자 지원 버전

### 제목

두 사람의 오늘을 빠르게 파악하도록 설계한 모바일 React PWA

### 우선 강조

1. 문제 발견부터 사용자 흐름과 MVP 범위 결정
2. 함께·본인·파트너의 일관된 정보 구조와 색상 언어
3. 375px, 44px 터치 영역, safe area, 바텀시트 UX
4. Page·Component·Hook·Store·Service의 책임 구분
5. 서버 상태와 Zustand 클라이언트 상태를 분리한 이유
6. Realtime 구독의 생성·gap·멱등 반영·cleanup
7. 로딩·빈 상태·오류·삭제 확인 등 상태별 사용자 경험
8. PWA 설치와 Push 알림에서 관련 날짜로 복귀하는 흐름

### 30초 직무 연결 답변

> React 화면을 만드는 데 그치지 않고 사용자가 오늘 할 일을 빠르게
> 파악하는 정보 구조부터 설계했습니다. 서버 데이터는 Hook이 조회와
> Realtime 구독을 관리하고, 사용자·커플 컨텍스트와 UI 상태만 Zustand에
> 두었습니다. 실제 채널 누적으로 캘린더가 멈춘 문제를 구독 cleanup과
> 클라이언트 수명주기 관점에서 해결한 경험이 있습니다.
