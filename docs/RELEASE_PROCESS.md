# 하루투두 버전 및 배포 관리

## 기준

앱 버전의 단일 기준은 `package.json`의 `version`이다. `package-lock.json`의 최상위/루트 패키지 버전은 함께 변경하며, 마이페이지는 이 값을 직접 읽는다. 개발 서버에서는 `· 개발`을 덧붙이고 운영 빌드에는 표시하지 않는다.

| 구분 | 올리는 때 | 예시 |
|---|---|---|
| Patch | 기존 기능의 오류, 문구, 간격, 작은 배치 개선 | 1.1.0 → 1.1.1 |
| Minor | 호환되는 새 기능 추가 또는 의미 있는 기능 확장 | 1.1.1 → 1.2.0 |
| Major | 기존 사용 흐름이나 데이터 호환성을 깨는 변경 | 1.2.0 → 2.0.0 |

하루투두 제품에 맞춘 SemVer 운영 기준이다. 큰 숫자를 올리면 뒤 숫자는 0으로 초기화한다. 여러 변경을 한 번에 배포하면 가장 높은 변경 등급 하나를 적용한다. 빌드를 실행하거나 개발 중 파일을 수정할 때마다 숫자를 올리지 않는다.

## 개발 중

1. 기능·개선·오류 수정을 마칠 때 `CHANGELOG.md`의 `[Unreleased]` 아래에 사용자 관점의 변경을 적는다.
2. 보고 시 예상 버전 등급을 정리한다. 작업 중인 배포 버전에 포함할 보완은 해당 준비 기록에 함께 반영한다.
3. `1.1.0`은 이번 의견함을 포함한 새 기준이며 이전 운영 상태에 소급해 `1.0.0` 태그를 만들지 않는다.

## 다음 배포 준비

다음 중 하나를 실행한다. npm 기본 기능으로 두 버전 파일만 갱신하며 Git 커밋/태그를 자동으로 만들지 않는다.

```sh
npm run version:patch
npm run version:minor
npm run version:major
```

선택된 새 버전의 `## [버전] - 배포 준비` 섹션을 CHANGELOG에 만들고 Unreleased 내용을 이동한다. 같은 배포 묶음은 다시 증가시키지 않는다. 변경이 여러 개면 Minor/Major 우선 기준을 따른다.

`lib/content/releaseNotes.json`에도 새 버전과 사용자에게 보여줄 변경 사항을 한 문장씩 작성한다. 앱 버전과 이 안내 버전이 다르거나 내용이 비어 있으면 CI·빌드를 중단한다. 업데이트 안내는 로그인한 사용자의 첫 앱 진입에 표시하며 ‘확인했어요’를 눌렀을 때 해당 버전의 확인 기록을 기기 브라우저에 저장한다. 다른 기기·브라우저나 앱 데이터 삭제 후에는 다시 표시될 수 있다. 비공개 모드 등으로 저장이 차단되면 현재 실행 중에는 닫힘을 유지하지만 다음 실행의 재표시를 보장할 수 없다.

```sh
npm run version:check
npm run verify
```

검증은 버전 형식, package/lock 두 위치의 일치, 현재 버전의 CHANGELOG 섹션 존재를 확인한다. `prebuild`와 CI에도 연결해 기록 누락을 차단한다. 변경 등급이나 실제 배포 여부까지 자동 판단하는 도구는 아니므로 변경 내용 검토를 함께 한다.

## 운영 배포

1. 앱·DB·Edge Function·Storage·예약 작업별 적용 대상을 점검한다. 개발 반영과 운영 반영을 구분해 보고한다.
2. 검증을 마친 배포 커밋을 고정하고 실제 운영 배포를 진행한다. 미커밋 변경이 있으면 그 상태를 배포 태그로 기록하지 않는다.
3. 정상 동작 확인 후 변경 기록의 ‘배포 준비’를 실제 한국 시간 배포일로 바꾸고, 배포 커밋 SHA/DB 및 함수 적용 내역을 남긴다.
4. 실제 배포 커밋에 `v1.1.0` 같은 Git 태그를 만든다. 태그/원격 push는 배포 승인을 받은 범위에서 수행한다. 출시한 버전의 다른 코드로 태그를 이동하지 않는다.
5. 새 코드가 더해진 수정 배포는 새 Patch 등급 이상으로 준비한다. 긴급 복구는 기존 배포 커밋으로 되돌리고 복구 대상을 기록한다.

빌드의 정확한 식별자는 CI/배포 시스템의 커밋 SHA와 배포 실행 기록으로 추적한다. 사용자가 보는 마이페이지에는 앱 버전만 조용히 표시한다. 앱 버전 숫자를 바꾸는 것만으로 PWA 캐시가 갱신되지는 않으므로 SW 변경 시 기존 캐시 정책도 따로 검수한다.
